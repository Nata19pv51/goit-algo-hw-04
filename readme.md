Основна мета роботи було порівняння ефективності трьох алгоритмів сортування: Insertion Sort, Merge Sort та Timsort. В якості даних брали випадково згенеровані числові списки різної довжини як вхідні дані. Результати експерименту візуалізовано на двох графіках: "Small_array_sort.png" (для малих обсягів даних: N = 5 - 50) та "Big_array_sort.png" (для великих обсягів даних: N = 100 - 2000), які можуть бути відтворені при запуску програми. З графіку "Small_array_sort.png" видно, що при малому обсязі даних (N <= 50) алгоритм Insertion Sort виявився найшвидшим серед трьох досліджуваних методів. Однак при збільшенні кількості даних його швидкість суттєво зменшувалась, і він стаавв найповільнішим. Це є очевидним, оскільки для випадково згенерованих вхідних даних (середній випадок) його часова складність сягає O(N2). 

Для Merge Sort і Timsort отримали іншу закономірність. На маленьких обсягах даних Merge Sort був найповільнішим, але зі збільшенням N його ефективність зростала відносно Insertion Sort. Це пояснюється з його часовою складністю O(N logN), яка обумовлена двома основними кроками алгоритму - "розділяй" і "володарюй". Timsort є гібридним алноритмом, який поєднує  Insertion Sort і Merge Sort, що дало змогу пришвидшити обробку даних і забезпечити більш стабільну та високу продуктивність. На графіку "Big_array_sort.png" показано, що ефективність Merge Sort і Timsort залишається постійною O(N logN) незалежно від вихідного порядку елементів у масиві, на відміну від Insertion Sort.

Було також проведено додаткове порівняння обраних алгоритмів зі стандартною функцією sort() в Python, в онові якої лежить Timsort. З графіків видно, що швидкість роботи sort() є стабільно високою як на малих, так і на великих обсягах даних. В порівнянні з реалізацією Timsort, стандартний метод виявився швидким, що свідчить про використання в його реалізації додаткових оптимізаційних решень.
